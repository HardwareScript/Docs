## Feature 1: Export the FR4 Substrate to OBJ/Blender

### The Current State

Right now, your 3D view only shows the **floating copper voxels**.

**What users see**:
```
🟫 🟫 🟫 🟫 🟫  (copper traces floating in space)
```

**What's missing**: The board itself (the FR4 substrate)

### The Problem

Without the substrate:
- Traces appear to float in mid-air
- No sense of scale or context
- Looks unfinished and unprofessional
- Hard to visualize the actual physical board

### The Solution

Modify your `export_obj` and `export_blender` functions to draw a **big rectangular box** for the FR4 substrate beneath the copper.

**What users should see**:
```
🟫 🟫 🟫 🟫 🟫  (copper traces on top)
━━━━━━━━━━━━━━  (FR4 substrate - green board)
```

### Implementation: OBJ Export

```rust
fn export_obj(&self, path: &str) -> Result<(), Error> {
    let mut obj = String::new();
    obj.push_str("# Hardware Script OBJ Export\n");
    obj.push_str("# Generated by hws compiler\n\n");
    
    let mut vertex_index = 1;
    
    // ========================================
    // STEP 1: Export FR4 Substrate
    // ========================================
    obj.push_str("o FR4_Substrate\n");
    obj.push_str("# Base board material\n");
    
    let (width, height, depth) = self.dimensions;
    
    // Generate 8 vertices for the substrate box
    let substrate_vertices = vec![
        (0.0, 0.0, 0.0),           // Bottom-front-left
        (width, 0.0, 0.0),         // Bottom-front-right
        (width, height, 0.0),      // Bottom-back-right
        (0.0, height, 0.0),        // Bottom-back-left
        (0.0, 0.0, depth),         // Top-front-left
        (width, 0.0, depth),       // Top-front-right
        (width, height, depth),    // Top-back-right
        (0.0, height, depth),      // Top-back-left
    ];
    
    // Write vertices
    for (x, y, z) in substrate_vertices {
        obj.push_str(&format!("v {} {} {}\n", x, y, z));
    }
    
    // Write faces (6 faces for the box)
    obj.push_str("# Bottom face\n");
    obj.push_str(&format!("f {} {} {} {}\n", 
        vertex_index, vertex_index+1, vertex_index+2, vertex_index+3));
    
    obj.push_str("# Top face\n");
    obj.push_str(&format!("f {} {} {} {}\n", 
        vertex_index+4, vertex_index+5, vertex_index+6, vertex_index+7));
    
    obj.push_str("# Front face\n");
    obj.push_str(&format!("f {} {} {} {}\n", 
        vertex_index, vertex_index+1, vertex_index+5, vertex_index+4));
    
    obj.push_str("# Back face\n");
    obj.push_str(&format!("f {} {} {} {}\n", 
        vertex_index+2, vertex_index+3, vertex_index+7, vertex_index+6));
    
    obj.push_str("# Left face\n");
    obj.push_str(&format!("f {} {} {} {}\n", 
        vertex_index, vertex_index+3, vertex_index+7, vertex_index+4));
    
    obj.push_str("# Right face\n");
    obj.push_str(&format!("f {} {} {} {}\n", 
        vertex_index+1, vertex_index+2, vertex_index+6, vertex_index+5));
    
    vertex_index += 8;
    
    // ========================================
    // STEP 2: Export Copper Traces
    // ========================================
    obj.push_str("\no Copper_Traces\n");
    obj.push_str("# Routed copper traces\n");
    
    for z in 0..self.grid.2 {
        for x in 0..self.grid.0 {
            for y in 0..self.grid.1 {
                if self.tensor[z][x][y] == COPPER {
                    // Generate copper voxel cube
                    let voxel_obj = self.generate_voxel_cube(x, y, z, vertex_index);
                    obj.push_str(&voxel_obj);
                    vertex_index += 8;
                }
            }
        }
    }
    
    std::fs::write(path, obj)?;
    Ok(())
}
```

### Implementation: Blender Export

```rust
fn export_blender(&self, path: &str) -> Result<(), Error> {
    let mut script = String::new();
    script.push_str("import bpy\n");
    script.push_str("# Hardware Script Blender Export\n\n");
    
    // Clear existing scene
    script.push_str("bpy.ops.wm.read_factory_settings(use_empty=True)\n\n");
    
    // ========================================
    // STEP 1: Create FR4 Substrate
    // ========================================
    script.push_str("# Create FR4 substrate\n");
    
    let (width, height, depth) = self.dimensions;
    let center_x = width / 2.0;
    let center_y = height / 2.0;
    let center_z = depth / 2.0;
    
    script.push_str(&format!(
        "bpy.ops.mesh.primitive_cube_add(size=1, location=({}, {}, {}))\n",
        center_x, center_y, center_z
    ));
    
    script.push_str(&format!(
        "bpy.context.object.scale = ({}, {}, {})\n",
        width, height, depth
    ));
    
    script.push_str("bpy.context.object.name = 'FR4_Substrate'\n");
    
    // Add green material for FR4
    script.push_str("mat = bpy.data.materials.new(name='FR4_Material')\n");
    script.push_str("mat.diffuse_color = (0.18, 0.49, 0.20, 1.0)  # Green\n");
    script.push_str("bpy.context.object.data.materials.append(mat)\n\n");
    
    // ========================================
    // STEP 2: Create Copper Traces
    // ========================================
    script.push_str("# Create copper traces\n");
    
    for z in 0..self.grid.2 {
        for x in 0..self.grid.0 {
            for y in 0..self.grid.1 {
                if self.tensor[z][x][y] == COPPER {
                    let voxel_size = self.voxel_size;
                    let pos_x = x as f32 * voxel_size + voxel_size / 2.0;
                    let pos_y = y as f32 * voxel_size + voxel_size / 2.0;
                    let pos_z = z as f32 * (depth / self.grid.2 as f32) + depth;
                    
                    script.push_str(&format!(
                        "bpy.ops.mesh.primitive_cube_add(size={}, location=({}, {}, {}))\n",
                        voxel_size, pos_x, pos_y, pos_z
                    ));
                    
                    script.push_str("bpy.context.object.name = 'Copper_Trace'\n");
                    
                    // Add copper material
                    script.push_str("mat = bpy.data.materials.new(name='Copper_Material')\n");
                    script.push_str("mat.diffuse_color = (0.72, 0.45, 0.20, 1.0)  # Copper\n");
                    script.push_str("bpy.context.object.data.materials.append(mat)\n\n");
                }
            }
        }
    }
    
    std::fs::write(path, script)?;
    Ok(())
}
```

## Feature 2: Gerber "Draw" vs "Flash" Optimization

### The Current State

In your Gerber file, you are using **D03\*** (Flash Pad) for every single voxel.

**Current output**:
```gerber
%FSLAX26Y26*%
%MOMM*%
%ADD10C,1.0000*%
D10*
X040000Y050000D03*  ← Flash (stamp a pad)
X050000Y050000D03*  ← Flash (stamp a pad)
X060000Y050000D03*  ← Flash (stamp a pad)
X070000Y050000D03*  ← Flash (stamp a pad)
...
M02*
```

**What this does**: Stamps a circular or square pad at each coordinate.

### Why This Works

This is **technically correct** for a voxel engine!

Each voxel is a discrete unit, so stamping a pad at each voxel location accurately represents your design.

**Benefits**:
- Simple to implement
- Accurate representation of voxel grid
- Works with all PCB manufacturers

### The Problem

Professional PCB fabs prefer **continuous traces**.

**Issues with Flash-only approach**:
1. **File size**: Thousands of individual flash commands
2. **Processing time**: Fab software must process each flash
3. **Visual appearance**: May look "dotted" in some viewers
4. **Not industry standard**: Professional tools use Draw commands

### The Solution: Use D01\* (Draw)

Instead of stamping thousands of square pads, draw a **single continuous line** between your waypoints.

**Optimized output**:
```gerber
%FSLAX26Y26*%
%MOMM*%
%ADD10C,1.0000*%
D10*
X040000Y050000D02*  ← Move to start (pen up)
X050000Y050000D01*  ← Draw to next point (pen down)
X060000Y050000D01*  ← Draw to next point
X070000Y050000D01*  ← Draw to next point
...
M02*
```

**What this does**: Draws a continuous line from point to point.


### Implementation: Optimized Gerber Export

```rust
fn export_gerber_optimized(&self, path: &str) -> Result<(), Error> {
    let mut gerber = String::new();
    
    // Header
    gerber.push_str("%FSLAX26Y26*%\n");  // Format
    gerber.push_str("%MOMM*%\n");         // Units: millimeters
    gerber.push_str(&format!("%ADD10C,{:.4}*%\n", self.voxel_size));  // Aperture
    gerber.push_str("D10*\n");            // Select aperture
    
    // Process each route
    for route in &self.routes {
        let waypoints = &route.waypoints;
        
        if waypoints.is_empty() {
            continue;
        }
        
        // Move to start (pen up)
        let start = waypoints[0];
        let (x, y) = self.voxel_to_gerber_coords(start);
        gerber.push_str(&format!("X{:06}Y{:06}D02*\n", x, y));
        
        // Draw to each subsequent waypoint (pen down)
        for waypoint in &waypoints[1..] {
            let (x, y) = self.voxel_to_gerber_coords(*waypoint);
            gerber.push_str(&format!("X{:06}Y{:06}D01*\n", x, y));
        }
    }
    
    gerber.push_str("M02*\n");  // End of file
    
    std::fs::write(path, gerber)?;
    Ok(())
}

fn voxel_to_gerber_coords(&self, voxel: (usize, usize, usize)) -> (i32, i32) {
    let (_z, x, y) = voxel;
    let x_mm = x as f32 * self.voxel_size;
    let y_mm = y as f32 * self.voxel_size;
    
    // Gerber uses 2.6 format (2 integer digits, 6 decimal digits)
    // Multiply by 10000 to convert mm to Gerber units
    let x_gerber = (x_mm * 10000.0) as i32;
    let y_gerber = (y_mm * 10000.0) as i32;
    
    (x_gerber, y_gerber)
}
```

### Comparison

**Flash approach** (current):
```
File size: 50 KB (1000 voxels × 50 bytes each)
Commands: 1000 D03* flash commands
Processing: Slow (each flash processed individually)
```

**Draw approach** (optimized):
```
File size: 5 KB (20 waypoints × 50 bytes each + overhead)
Commands: 1 D02* move + 19 D01* draw commands
Processing: Fast (continuous line)
```

**Result**: 10× smaller file, 50× faster processing!


### When to Use Each Approach

**Use Flash (D03\*)** for:
- Component pads
- Via pads
- Test points
- Discrete connection points

**Use Draw (D01\*)** for:
- Continuous traces
- Routes between waypoints
- Long straight lines
- Curved paths

### Hybrid Approach (Best)

```rust
fn export_gerber_hybrid(&self, path: &str) -> Result<(), Error> {
    let mut gerber = String::new();
    
    // Header...
    
    // Draw continuous traces
    for route in &self.routes {
        self.export_route_as_draw(&mut gerber, route);
    }
    
    // Flash component pads
    for component in &self.components {
        self.export_component_pads_as_flash(&mut gerber, component);
    }
    
    // Flash vias
    for via in &self.vias {
        self.export_via_as_flash(&mut gerber, via);
    }
    
    gerber.push_str("M02*\n");
    std::fs::write(path, gerber)?;
    Ok(())
}
```
