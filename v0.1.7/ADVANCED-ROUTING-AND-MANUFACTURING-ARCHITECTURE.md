## Section 1: The Symmetrical & Length-Matching Pattern Engine

Patterns are treated as **Geometric Generators** that modify or replace the raw segment coordinates generated by the pathfinder, adapting natively to both PCB and ASIC scales.

### 1.1 PCB Patterns: Trombone / Serpentine Length Matching
For high-speed buses requiring identical length matching (e.g., DDR5), the pattern engine:
1.  Calculates the shortest geometric path for all traces in the signal group.
2.  Identifies the longest trace and sets its length as the target.
3.  For any shorter trace with a length deficit, it identifies unobstructed 2D zones along the path and inserts a series of parameterized "folds" (Serpentine/Trombone) to consume the exact length difference.

### 1.2 ASIC Patterns: Symmetrical H-Tree / X-Tree Synthesis
For clock distribution networks on silicon dies requiring near-zero clock skew:
1.  Bypasses point-to-point pathfinding.
2.  Calculates the global bounding box of all target registers.
3.  Generates the recursive, fractal coordinates for a symmetrical N-depth H-Tree.
4.  Maps the segments to designated metal layers (e.g., horizontal lines on M4, vertical on M3) and automatically schedules buffer placement at splitting nodes.

## Section 2: The "Bouncer vs. Butler" Ohmic Bridge Paradigm

To bridge the gap between abstract logical routing and exact material chemistry, the compiler operates under the **"Bouncer at Assembly, Butler at Router"** principle.

-   **Assembly Level (The Bouncer)**: The compiler does not automatically inject intermediate contact materials (e.g., Silicide between Silicon and Metal) during manual placements. If a user manually places incompatible materials, the DRC halts the build with **Error P45: Forbidden Junction**.
-   **Router Level (The Butler)**: When using the high-level `route` command, the router automatically reads the active Profile's bridge table and stamps the necessary compound via stacks at material transitions.

### The Via-Stamping "Sandwich" Rule
The auto-via inserter creates a **Compound Via** by stamping exactly one voxel layer of the specified bridge material (e.g., `Titanium_Silicide`) at the exact boundary, and filling the rest of the vertical column with the low-resistance fill material (e.g., `Tungsten`).

### 2.1 Post-Realization Structural Integrity (v0.1.7)
To ensure the "Butler" principle holds for manual routing, the compiler runs a **Post-Realization Drill Pass**. This pass re-analyzes the physical board after manual traces are converted to copper, ensuring that any trace overlapping a via is correctly carved with the appropriate structural hole.

## Section 3: Code-Defined Dummy Metal Fill (Thieving)

To prevent silicon wafer warping during Chemical-Mechanical Polishing (CMP) or to maintain uniform copper density on high-frequency PCBs, the compiler supports **Dummy Metal Fill (Thieving)**.

To prevent infinite compile-time overhead during active development, Dummy Fill is defined as a first-class script property inside the profile or space definition.

```hardware
profile TSMC_180nm:
    # Code-defined thieving configuration inside the profile
    dummy_fill: true
    dummy_fill_density: 45%
    dummy_fill_pattern: DotGrid(size: 2um, spacing: 4um)
```

### The Post-Routing Thieving Pass
When `dummy_fill: true` is set, the compiler runs a post-routing pass:
1.  Divides the routing layer into coarse zones.
2.  Calculates the current metal density of each zone.
3.  If density is below target, it stamps isolated, non-functional squares (dummies) into the empty regions of the voxel grid, maintaining minimum clearance from routed nets.

## Section 4: High-Speed Signal Integrity (SI)

### 4.1 Reference-Plane Aware Routing
High-speed signals must never cross a "split" or "void" in the underlying ground/power plane. The 2.5D Analytic Router is **Substrate-Aware** during cost-calculation:
-   Path over solid copper = Low SI Cost.
-   Path over dielectric void = High SI Cost.

### 4.2 DFM Artifacts: The "Teardrop"
Industry standard DFM requires adding a filleted transition (teardrop) where a trace enters a pad or via to prevent mechanical failure during drilling. The `AnalyticTrace` primitive supports Junction Filleting, automatically generated based on the Profile's reliability class (IPC Class 2 vs. Class 3).

### 4.3 Via Stubs and Back-Drilling
The compiler identifies "Unused Via Depth" (Stubs) at GHz frequencies and either flags them as SI violations or automatically schedules a Back-Drill operation in the Excellon export.
